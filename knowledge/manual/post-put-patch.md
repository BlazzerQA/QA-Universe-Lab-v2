# POST vs PUT vs PATCH

📝 POST — создание ресурса, PUT — замена ресурса целиком, PATCH — редактирование ресурса.

📝 POST запрос вообще может делать всё что угодно- передавать данные серверу, удалять и тд, ваще хоть что. А PUT/PATCH — предсказуемые.

📝 При отправке PUT по несуществующему id- происходит создание элемента.

## Таблица сравнения

| Свойство | POST | PUT | PATCH |
|----------|------|-----|-------|
| Назначение | Отправка данных (создание, изменение, обновление) | Обновляем все поля (всю строку) | Обновляем одно или больше полей (ячейку) |
| Статус коды | 200 OK (id в body), 201 Created (id в Headers “Location”), 204 No Content | 200 OK, 201 Created (если ранее не было ресурса), 204 No Content | 200 OK, 204 No Content |
| URL указывает на | “Контейнер” ресурсов, в который будет добавлен новый | Конкретный ресурс, который будет заменен | Конкретный ресурс, который будет частично обновлен |
| Данные в запросе | Полное представление нового ресурса | Полное представление нового ресурса | Те данные, которые надо обновить |
| Идемпотентность | Нет | Да | Нет |
| Запрос к несуществующему id приведет к? | Созданию нового элемента | Созданию нового элемента | Ошибке |

## Пример PUT (кот Буся)

Объект в базе:

- "id": 1
- "name": "Буся"
- "age": 3 (необязательное поле)

Отправляем PUT запрос с body:

- "id": 1
- "name": "Машка"

PUT изменяет все поля. То, что не передали = null. Объект станет:

- "id": 1
- "name": "Машка"
- "age": null

## Пример PATCH (тот же кот)

PATCH изменяет только те поля, которые передали. То, что не изменили, остается без изменений. Отправляем то же body:

- "id": 1
- "name": "Машка"

Объект станет:

- "id": 1
- "name": "Машка"
- "age": 3

⚠️ На собесе любят спрашивать: “что будет с полем age при PUT и PATCH, если его не передать?” Ответ: при PUT станет null, при PATCH останется как был.
