# Виды тестирования

## Функциональное

📝 Функциональное- то, что прописано в требованиях:

- GUI (интерфейса) — ЗАВИСИТ ОТ КОНКРЕТНОЙ ЗАДАЧИ
- Безопасности — ЗАВИСИТ ОТ КОНКРЕТНОЙ ЗАДАЧИ

По степени автоматизации:

- Ручное
- Автоматизированное

По сценариям:

- Позитивное
- Негативное

По знанию системы:

- Белого ящика
- Серого ящика
- Черного ящика

По исполнению кода:

- Статическое
- Динамическое

По исполнителям:

- Альфа
- Бета (открытое/ закрытое)

## Нефункциональное

- Инсталляционное- установка, обновление, обновление с первой версии на третью, удаление
- Удобства использования (usability)- кнопки норм расположены, цвета приятны глазу, удобная и понятная навигация, “обучаемость” пользователей (на сколько быстро юзер поймет, как пользоваться сайтом)
- Локализации- корректность перевода языка, валюты, мер измерений
- На отказ и восстановление- сохранность данных после сбоев

## Производительности

- Нагрузочное- тест различных уровней нагрузки до предельного значения (из требований). Замеряем время отклика системы, скорость обработки запросов, сколько сетевых, процессорных ресурсов “съедает” система.
- Стрессовое- тест системы при нагрузке выше нормы
- Объемное- когда тысячи пользователей отправляют одновременно энное количество байт информации
- Стабильности (надежности)- средний уровень нагрузки, но при длительной работе
- Масштабируемости- проверяем, что при резком увеличении пользователей/ запросов система будет масштабироваться (включаться дополнительные сервера)

## Конфигурационное

- Конфигурационное- всё норм работает при различных конфигурациях системы (Windows 10 + Opera)
- Кроссбраузерное- всё норм работает в разных браузерах
- Кроссплатформенное- всё норм работает на разных ОС
- Интернационализации

## По уровню тестирования

- Модульное (компонентное/ unit)- тестирование чего-то одного- функций, классов, модулей. Выполняется программистами. 💡 Пример: В яндекс go корректно определяется местоположение
- Интеграционное- проверка корректности взаимодействия нескольких модулей. 💡 Пример: Корректно определяется местоположение и можно ввести данные в поле “место назначения” на другом экране
- Системное- проверка функциональных и нефункциональных требований
- Приемочное- проверяет соответствие системы потребностям и требованиям пользователя

## Связанные с изменениями

📝 Все эти тесты проводятся после каких-то изменений (добавление новой фичи, новый билд приложения, миграция на другую ОС или БД):

- Дымовое (Smoke)
- Санитарное (Sanity)
- Регрессионное (Regression)
- Ре-тест (повторное)

💡 Подробно каждый из четырех разобрал в статье Smoke, Sanity, Regression, Re-testing.
