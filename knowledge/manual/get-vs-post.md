# GET vs POST

📝 POST запрос вообще может делать всё что угодно- передавать данные серверу, удалять и тд, ваще хоть что.

## Таблица сравнения

| Свойство | GET | POST |
|----------|-----|------|
| Назначение | Получение данных | Отправка данных (создание, изменение, обновление) |
| Способ передачи данных | Через URL | Через Body |
| Объем передаваемых данных | Ограничен URL (2048 символов) | Ограничений нет (могут быть установлены сервером) |
| Возможность отправки файлов | Нет | Да |
| Возможность сохранения | Можно скопировать и сохранить в закладках | Нельзя сохранить в закладки |
| Кэшируется? | Да | Нет |
| Скорость обработки | Быстрее за счет пустого body | Медленее из-за body |
| Защита данных | Данные видны в адресной строке, в истории = не защищены | Данные можно увидеть с помощью инструмента разработчика, расширений браузера, спец. программ |
| Поддержка соединения | Не разрывает (при включенном на сервере режиме keepAlive) | Разрывает |
| Идемпотентный? | Да | Нет |

## Еще вариант ответа

📝 У них разный смысл: GET — это запрос на получение данных, а POST — это запрос на отправку данных.

📝 Согласно REST рекомендациям — в GET запросах не используется body (технически body есть), в POST body используется.

📝 GET — идемпотентный, а POST нет. (идемпотентность — свойство запроса, при котором повторная отправка этого же запроса НЕ меняет состояние сервера)

📝 GET — безопасный метод, в отличии от POST.

## Какой метод безопаснее?

📝 POST безопаснее:

- Передает данные в теле запроса (GET передает в URL)
- Не имеют ограничений в длине запроса (GET ограничен длиной URL — около 2048 символов)
- Не кэшируется (GET кэшируются)
- Не сохраняются в логах (GET могут сохраняться в логах сервера, браузера и прокси-серверов)

💡 В проекте друга: GET /api/notes получает список статей — данные в URL, можно кэшировать. А вход по телефону и паролю должен идти через POST — чтобы пароль не светился в URL и логах.
