# REST vs SOAP

📝 REST — это архитектурный стиль. Набор рекомендаций. SOAP — это протокол, по которому веб-сервисы взаимодействуют друг с другом.

В REST все делается с помощью HTTP-методов: GET, POST, PUT, DELETE, OPTIONS и PATCH.

## REST

📝 Representational State Transfer — передача репрезентативного состояния.

- Пример реализации — JSON через HTTP
- Обмен сообщениями через JSON (в большинстве случаев), XML или любой другой формат
- Определение услуг через Swagger, GitHub, Wiki
- Для тестирования используем Postman

## SOAP

📝 Simple Object Access Protocol — простой протокол доступа к объектам.

- Пример реализации — XML поверх SOAP через HTTP
- Обмен сообщениями через XML
- Определение услуг через WSDL
- Для тестирования используем SOAP UI

## Плюсы REST

- Гибкость
- Позволяет кешировать данные
- Поддержка нескольких форматов

## Минусы REST

- Нет единой структуры REST (есть рекомендации, а не правила)
- Большие полезные нагрузки (возвращает много метаданных)
- Проблемы чрезмерных или недостаточных данных (приходится делать дополнительный запрос)

## Плюсы SOAP

- Независимость от языка и платформы
- Связанность с различными транспортными протоколами
- Встроенная обработка ошибок
- Ряд расширений безопасности

## Минусы SOAP

- Только XML
- Тяжеловесность (XML-файлы большие)
- Узкоспециализированные знания

## Другой вариант ответа на собесе

REST — это архитектурный стиль, правила которого желательно соблюдать.

SOAP — это протокол, важно строго соблюдать все его правила.

REST:

- SOAP поддерживает только формат XML
- REST поддерживает различные форматы (JSON, XML и другие)
- Разные типы запросов — GET, POST, PUT, DELETE, PATCH
- REST работает только по протоколу HTTP (или HTTPS)
- Часть запросов может быть закэширована
- Документация обычно в Swagger или в OpenAPI формате
- Инструмент для тестирования — Postman

SOAP:

- Один общий тип запросов (похож на POST)
- SOAP работает с различными протоколами (HTTP, SMTP, FTP)
- В SOAP не предусмотрено кэширование
- Документация в WSDL (вэ-эс-дэ-элька)
- Инструмент для тестирования — SOAP UI
- Сообщение длиннее и менее читабельны, так как в запросе всегда есть обертка, а информацию передаем внутри тега body:

```xml
<Envelope>
  <Header></Header>
  <Body>
    <userData>
      <login>german</login>
      <password>123</password>
    </userData>
  </Body>
</Envelope>
```markdown
