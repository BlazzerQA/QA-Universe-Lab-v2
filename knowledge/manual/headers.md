# Headers в Postman

📝 Настройка Headers важна для правильного взаимодействия между клиентом (Postman) и сервером (API) для получения ожидаемых ответов. Они предоставляют дополнительную информацию, необходимую для правильной обработки запросов и ответов.

Там же мы передаем токены или ключи API.

## 9 основных хэдеров

1. **Cache-control** — указывает, как кэшировать ответ на стороне клиента. `no-cache` запрещает кэширование, а `max-age=3600` — ответ кэшировать до 1 часа.

2. **Postman-token** — токен для идентификации запроса в Postman.

3. **Host** — указывает, к какому домену отправлен запрос (нужен, когда URL не указан или требуется указать хост).

4. **User-Agent** — с помощью него сервер идентифицирует клиента, который сделал запрос (в зависимости от этого может быть разный ответ).

5. **Accept** — какие типы клиент будет обрабатывать в ответе, например `application/json`, `*/*` — все MIME типы медиаданных.

6. **Accept-encoding** — какие методы сжатия ответа клиент может обрабатывать, например `gzip`, `deflate` и другие.

7. **Connection** — как клиент и сервер управляют соединением после запроса, например `keep-alive` или `close`.

8. **Content-Type** — указывает MIME тип содержимого в теле запроса или ответа.

9. **Content-Length** — указывает размер (в байтах) содержимого, передаваемого в теле запроса или ответа.

## Что такое хэдеры простыми словами

📝 Хэдеры — это часть HTTP запроса. В них передают мета-информацию про запрос, например, какой используется браузер или какой формат сообщения в body: JSON или XML.

Примеры:

- **Content-Type** для обозначения формата сообщения
- **User-agent** для обозначения типа клиента
- **Cookie** для передачи куки из браузера
- **Set-Cookie** в ответе от сервера, чтобы сохранить куку в браузер
- **Cache-control** для управления откуда взять данные: из кэша или с сервера
