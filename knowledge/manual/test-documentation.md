# Виды документации

## Тест план

📝 Тест план- документ, описывающий весь объем работ по тестированию. Начиная с описания тестируемых объектов, стратегии, расписания, критериев начала и окончания тестирования до необходимого в процессе оборудования, спец знаний, а также оценки рисков с вариантами их решений.

Состоит из: видов тестирования, приоритетов, стратегий, окружений, задач, документации, техник тест-дизайна, баг-трекинга, критериев начала и окончания, инструментов для работы.

## Тест-suite

📝 Тест-suite- папка, которая содержит в себе набор тестов, предназначенных для проверки какой-то одной функциональности.

## Тест кейс

📝 Тест кейс- состоит из ID, названия проверки, пред-условий, тестовых данных, шагов для воспроизведения, ожидаемого результата.

## Чек лист

📝 Чек лист- состоит из модуля, подмодуля, тестируемого элемента/функции, названия проверки, статуса (passed/failed).

## User Story

📝 User Story- создается по шаблону: Я как (категория пользователей) - хочу (иметь возможность сделать) - чтобы (получить результат или ценность).

## Баг-репорт

📝 Баг-репорт- состоит из id, заголовок, описание, шаги воспроизведения, фактический + ожидаемый результат, на кого назначен, спринт, серьезность, приоритет, доп инфа (скрины и тп).

## Отчет по тестированию

📝 Отчет по тестированию- документ, содержащий инфу о выполненных действиях, результатах проведенной работы. Его делает руководитель QA для проджект менеджера.
